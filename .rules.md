# Coding guidelines

This file provides guidance to programming agents when working with code in this repository.

Crawlee for Python (`crawlee` on PyPI) is a web scraping and browser automation framework.

## Development

- Tasks live under `[tool.poe.tasks]` in `pyproject.toml` and are described in `CONTRIBUTING.md`. Run them with `uv run poe <task>`; set up with `uv run poe install-dev` (installs all extras, pre-commit hooks, and Playwright browsers).
- `uv run poe check-code` runs lint, type-check, and unit tests. Run a single test with `uv run pytest tests/unit/<path>.py::<test_name>`.
- `uv run poe unit-tests` first runs tests marked `@pytest.mark.run_alone` on their own, then the rest in parallel.
- Ruff, ty, and pytest settings are in `pyproject.toml`; docs examples (`docs/**/*.py`) have their own `docs/pyproject.toml`. `tests/unit/README.md` describes the unit-test fixtures and conventions.
- Don't introduce a shared Pydantic base model to centralize `model_config`. Each model inherits `pydantic.BaseModel` and declares `model_config = ConfigDict(...)` inline, which also keeps ruff's flake8-type-checking and `RUF012` checks working, since they only recognize a literal `pydantic.BaseModel` base.

## Commits

[Conventional Commits](https://www.conventionalcommits.org/); the types are listed in `CONTRIBUTING.md`. Choose the type by *what* changed, not just *why*:

- `feat:` / `fix:` / `perf:` / `refactor:` / `style:` — **source code only**; these trigger a release and appear in the changelog
- `test:` — test additions or changes (no release)
- `docs:` — documentation changes; also triggers a docs release on master
- `ci:` — CI/workflow changes
- `chore:` — dependency bumps, tooling, generated files, and other housekeeping
- `build:` — build system changes

Logging changes are breaking: changing a log level, a logger name, or the wording of a log message, or removing one, breaks downstream log-based tooling. Keep the accurate commit type, add `!`, and list the changes in a `BREAKING CHANGE:` footer. With squash-merge the `!` must be in the PR title.

## Docs, comments, and tests

- Never edit `website/versioned_docs/`. Those snapshots are release-automation output, frozen against the code that shipped. Fix `docs/` and the next release snapshot carries the change.
- Write `RQ` for the request queue in comments and docstrings. Log messages and public `.mdx` docs spell out the full term.
- Comments and docstrings describe what the code does now. The bug a change fixed, what a PR changed, and contrasts with removed behavior (`instead of ...`, `no longer ...`) belong in the commit message.
- Don't explain language features in comments. A comment earns its place with a domain reason, an invariant the types can't express, or a non-obvious consequence for callers.
- Use single backticks for code references in docstrings and comments, never RST-style double backticks.
- Wrap docstrings and prose comments to the full line length configured in `pyproject.toml`.
- Write only ASCII in source files: `->` instead of an arrow, `-` instead of a dash, straight quotes.
- Write flat `def test_*()` functions, never `class Test*`, and no section-header comments between tests.
- Almost every test gets a one-line docstring stating what it verifies, without a `Regression test:`-style prefix.
- In `@pytest.mark.parametrize`, wrap each case in `pytest.param(..., id='...')` with an id that describes the case.
- Use `Mock` and the `monkeypatch` fixture for test doubles, not hand-rolled stubs, counters, or flags.
- A test that changes process-wide or event-loop-wide state restores it. Prefer `monkeypatch`; for APIs it can't patch (`loop.set_exception_handler()`, `signal.signal()`, logging config, `os.chdir()`), capture the original value and restore it in a `finally`.
- For a TCP endpoint that must refuse connections, bind a socket to `('127.0.0.1', 0)` and hold it open without calling `listen()`. A hard-coded port can be taken by a server in a parallel xdist worker. Test servers use `127.0.0.1`, since on Windows `localhost` resolves to both IPv4 and IPv6.

## Architecture

### Crawler hierarchy

```text
BasicCrawler[TCrawlingContext, TStatisticsState]
├── AbstractHttpCrawler  →  HttpCrawler, BeautifulSoupCrawler, ParselCrawler, FileDownloadCrawler, PydanticAiCrawler
├── PlaywrightCrawler    →  StagehandCrawler
└── AdaptivePlaywrightCrawler (runs a static HTTP sub-crawler and a PlaywrightCrawler, picks per request)
```

`BasicCrawler` (`crawlers/_basic/`) owns the request lifecycle, autoscaling pool, retries, sessions, and router dispatch. `AbstractHttpCrawler` (`crawlers/_abstract_http/`) adds HTTP client integration, response parsing, and pre-navigation hooks.

### Context pipeline

Contexts are progressively enhanced through `ContextPipeline` middleware:

```text
BasicCrawlingContext → HttpCrawlingContext → ParsedHttpCrawlingContext → BeautifulSoupCrawlingContext
```

Each middleware is an async generator that wraps the next handler, enabling setup/teardown around request processing.

### Storage layer

Three-tier design:

- **High-level**: `Dataset`, `KeyValueStore`, `RequestQueue` in `src/crawlee/storages/`
- **Storage clients** (`src/crawlee/storage_clients/`): `FileSystemStorageClient` (default), `MemoryStorageClient`, `SqlStorageClient`, `RedisStorageClient`
- **Instance caching**: `StorageInstanceManager` is a global singleton that caches storage instances by ID/name

### Service locator

`src/crawlee/_service_locator.py` is a global singleton managing `Configuration`, `EventManager`, `StorageClient`, and `StorageInstanceManager`. Prevents double-initialization with `ServiceConflictError`.

### HTTP clients

Pluggable via `HttpClient` interface in `src/crawlee/http_clients/`:

- `ImpitHttpClient` (default), `HttpxHttpClient` (wraps the `httpx2` package), `CurlImpersonateHttpClient`
- Each provides `crawl()` (for crawler pipeline) and `send_request()` (for in-handler use)

### Request model

`Request` (`src/crawlee/_request.py`) uses `unique_key` for deduplication. Lifecycle (`RequestState`): `UNPROCESSED → BEFORE_NAV → AFTER_NAV → REQUEST_HANDLER → DONE`, with `ERROR_HANDLER → ERROR` on failure and `SKIPPED` for requests the crawler skips (currently only when disallowed by robots.txt). Crawlee-specific metadata stored in `user_data['__crawlee']`.
