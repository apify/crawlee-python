The <ApiLink to="class/SessionPool">`SessionPool`</ApiLink> class provides a robust way to manage the rotation of proxy IP addresses, cookies, and other custom settings in Crawlee. Its primary advantage is the ability to filter out blocked or non-functional proxies, ensuring that your scraper avoids retrying requests through known problematic proxies.

Additionally, it enables storing information tied to specific IP addresses, such as cookies, authentication tokens, and custom headers. This association reduces the probability of detection and blocking by ensuring cookies and other identifiers are used consistently with the same IP address.

Finally, it rotates sessions according to a configurable reuse strategy. This helps prevent overuse of a limited pool of available IPs, reducing the risk of IP bans and enhancing the efficiency of your scraper.

For more details on configuring proxies, refer to the [Proxy management](./proxy-management) guide. To read, set, and persist cookies, see [Cookie management](./cookie-management).

These examples demonstrate the basics of configuring and using the <ApiLink to="class/SessionPool">`SessionPool`</ApiLink>.

Please, bear in mind that <ApiLink to="class/SessionPool">`SessionPool`</ApiLink> requires some time to establish a stable pool of working IPs. During the initial setup, you may encounter errors as the pool identifies and filters out blocked or non-functional IPs. This stabilization period is expected and will improve over time.

## Choosing a reuse strategy

Set `session_reuse_strategy` on <ApiLink to="class/SessionPool#__init__">`SessionPool`</ApiLink> to control which session is reused:

- `'random'` (default) picks a random session.
- `'round-robin'` cycles through sessions in insertion order, for example `SessionPool(session_reuse_strategy='round-robin')`.
- `'use-until-failure'` keeps using the first usable session until it is retired, expires, or reaches its usage or error limit, then selects the next usable session.

All strategies fill the pool to `max_pool_size` before selecting a session. If the selected session is unusable and no existing session is selected for reuse, the pool removes unusable sessions and returns a new one. Selection position is kept in memory and restarts when the pool is reopened or reset; it is not persisted with the sessions.
