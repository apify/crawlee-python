[IP address blocking](https://en.wikipedia.org/wiki/IP_address_blocking) is one of the oldest and most effective ways of preventing access to a website. It is therefore paramount for a good web scraping library to provide easy to use but powerful tools which can work around IP blocking. The most powerful weapon in our anti IP blocking arsenal is a [proxy server](https://en.wikipedia.org/wiki/Proxy_server).

With Crawlee we can use our own proxy servers or proxy servers acquired from third-party providers.

## Proxy configuration

All our proxy needs are managed by the <ApiLink to="class/ProxyConfiguration">`ProxyConfiguration`</ApiLink> class. We create an instance using the <ApiLink to="class/ProxyConfiguration">`ProxyConfiguration`</ApiLink> constructor function based on the provided options.

Instead of `proxy_urls`, you can pass a `new_url_function`. It takes no arguments and returns a proxy URL, or `None` to use no proxy. It can be sync or async.

### IP Rotation and session management

Each call to <ApiLink to="class/ProxyConfiguration#new_proxy_info">`proxy_configuration.new_proxy_info()`</ApiLink> picks a proxy: the next URL from `proxy_urls`, or the one that `new_url_function` returns. The crawler's session pool calls it for every session it creates, and the session sends all its requests through that proxy. The session keeps its IP address together with its cookies, which creates the impression of a real user. When a session is retired, a new session takes its place with a newly picked proxy. See the <ApiLink to="class/SessionPool">`SessionPool`</ApiLink> class for more information on how maintaining a real session helps avoid blocking.

The proxy is picked once per session, not per request. In <ApiLink to="class/PlaywrightCrawler">`PlaywrightCrawler`</ApiLink>, pages share one browser context by default, and the context keeps the proxy of the session whose page opened it. To send every page through the proxy of its own session, pass `use_incognito_pages=True`.

When you pass your own <ApiLink to="class/SessionPool">`SessionPool`</ApiLink> to the crawler, pass `proxy_configuration` to the pool instead. The crawler doesn't accept both and raises an error.

For more details on session management, check out the [Session management](./session-management) guide.
