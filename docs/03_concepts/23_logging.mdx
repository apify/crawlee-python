Crawlee builds on the standard Python [`logging`](https://docs.python.org/3/library/logging.html) module. Each crawler logs to a logger named after its class under `crawlee.crawlers`, for example `crawlee.crawlers.HttpCrawler`. To use your own logger, pass it as the `logger` argument of the crawler. Inside a request handler the same logger is available as `context.log`, so you can log from your handlers without any setup.

## Default configuration

By default, a crawler sets up the logging infrastructure automatically when it's created. It attaches a handler with a human-readable, colored formatter to the root logger, unless the root logger already has handlers configured, the same way [`logging.basicConfig`](https://docs.python.org/3/library/logging.html#logging.basicConfig) does. You can opt out by passing `configure_logging=False` to the crawler's constructor and configure logging yourself. For the other constructor options, see <ApiLink to="class/BasicCrawlerOptions">`BasicCrawlerOptions`</ApiLink>.

The level of the root logger that the crawler configures comes from the <ApiLink to="class/Configuration#log_level">`Configuration.log_level`</ApiLink> option of the global configuration. It defaults to INFO, or DEBUG in Python's [development mode](https://docs.python.org/3/library/devmode.html), and can also be set through the `CRAWLEE_LOG_LEVEL` environment variable, for example:

```sh
CRAWLEE_LOG_LEVEL=DEBUG python main.py
```

The level has no effect when the crawler doesn't configure logging, except on the `httpx2` logger (see [Third-party loggers](#third-party-loggers)). For the other settings and the environment variables behind them, see [Configuration](./configuration).

The `crawlee` logger has a [`NullHandler`](https://docs.python.org/3/library/logging.handlers.html#logging.NullHandler). If neither Crawlee nor your application configures logging, Crawlee's logs go nowhere.

## Logger names

A crawler's autoscaled pool logs to the `autoscaled_pool` child of the crawler's logger, such as `crawlee.crawlers.ParselCrawler.autoscaled_pool`. The sub crawlers of <ApiLink to="class/AdaptivePlaywrightCrawler">`AdaptivePlaywrightCrawler`</ApiLink> log to the `static` and `playwright` children of its logger. The crawler sets these two loggers to ERROR when it's created, since it reports the outcome of each request itself. To see more from the sub crawlers, set the level of these loggers after you create the crawler.

The rest of Crawlee logs to loggers named after their modules, all under `crawlee`. Because the names form a hierarchy, you can set the level of a whole subtree:

```python
import logging

# Only warnings and errors from Crawlee.
logging.getLogger('crawlee').setLevel(logging.WARNING)

# The concurrency decisions of the autoscaling.
logging.getLogger('crawlee.autoscaling').setLevel(logging.DEBUG)
```

## Log levels

Crawlee picks the level of a message by who needs to act on it:

- ERROR: a request failed after all its retries, or the crawler can't go on.
- WARNING: a request is retried, a session is rotated, or something looks misconfigured.
- INFO: the crawler starts or finishes, and the periodic status and statistics.
- DEBUG: the steps of every request and the internal decisions, such as the autoscaling.

At DEBUG, the crawler logs these messages for every request:

- `Processing request` when it starts on the request.
- `Received a response` when an HTTP-based or Playwright crawler gets a response, with its `status_code`.
- `Committed the request handler result` when it stores the data and adds the requests from your handler, with the number of `push_data_calls` and `add_requests_calls`.
- `Request handled` when the request is done.

## Request context in log records

The request messages carry the request context as [`extra`](https://docs.python.org/3/library/logging.html#logging.Logger.debug) fields: `url`, `unique_key` and `retry_count`. Crawlee's formatter prints them after the message, and your own formatter can read them as attributes of the log record. The `Received a response` message adds `status_code` to them. ## Statistics logs

While running, the crawler periodically logs its statistics - requests finished and failed, retry histogram, durations, and more - and prints a final summary when the crawl ends. The `statistics_log_format` option of the crawler's constructor controls the output format: `table` (the default) renders the statistics as a formatted table, while `inline` logs them as a plain message with the values attached as extra fields, which is easier to consume with external log tooling. To change the logging interval or persist the statistics, see [Statistics](./statistics).

## Third-party loggers

The <ApiLink to="class/HttpxHttpClient">`HttpxHttpClient`</ApiLink> sets the `httpx2` logger to WARNING, because `httpx2` logs every request at INFO. When the configured log level is DEBUG, for example with `CRAWLEE_LOG_LEVEL=DEBUG`, it sets the logger to DEBUG. If you set a level on the `httpx2` logger before you create the client, the client keeps it.
